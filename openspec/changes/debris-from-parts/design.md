# Design

## Context

Всё, что летит и лежит после разрушения, идёт через `src/debris.rs`: сообщение `SpawnDebris`
(позиция, скорость, размер, цвет, горит ли) и один общий `Cuboid` 1×1×1, растянутый `scale` под
размер. Материал — на каждый цвет свой `StandardMaterial` без текстуры. Посадка на землю считает
половину высоты куба (`scale.y * 0.5`). Уснувший обломок хранится в `DebrisStore` по участкам как
`{transform, color}` и пересоздаётся кубом. Источники:

- дома — `collapse.rs` (плиты крыши и панели стен кубами в цветах `WALL_PALETTE`/`ROOF_PALETTE`,
  а не модели), руины `buildings.rs::spawn_ruin` (4 наклонных куба), выбитая дверь (8 кубиков-досок);
- валун и кварц — `props.rs::break_props` (кубы цвета из `STONE_COLORS`/`GEM_COLORS`) и
  `shatter()`, который копирует сетки прямых детей предмета: у предмета с загруженной моделью
  прямой ребёнок — корень сцены без сетки, поэтому осколков нет (кусты рассыпаются в ничто);
- враги, Служба — взрыв мощностью 0,25, ниже порога обломков 0,3: обломков нет;
- поезда — остов целиком, обломки только от общего взрыва;
- `explosion_fx.rs::throw_debris` — комья и горящие осколки кубами; туннель — 10 каменных кубов;
  тяжёлая пуля — кубик земли; термобарика — 6 горящих кубов.

Модели — glb из Meshy, одна сетка и один материал с текстурой (у новых домов ещё карты нормалей и
шероховатости), 1,5–8 тыс. треугольников. Сетки доступны через `Assets<Mesh>` после загрузки сцены.

## Goals / Non-Goals

**Goals:**
- Один механизм кусков модели для всего, что сделано моделью; одна библиотека форм для остального.
- Куски лежат и хранятся с формой и материалом, переживают выгрузку участка.
- Цена по кадрам не хуже нынешней при сносе посёлка.

**Non-Goals:**
- Физика твёрдых тел и столкновения обломков друг с другом и с машинами.
- Разрушение по месту попадания (дырка в стене от снаряда) — дом рушится целиком, как сейчас.
- Новые модели в Meshy под обломки.

## Decisions

### Куски модели режутся из её сетки при загрузке
При первой загрузке модели её треугольники делятся на N кусков (8–30 по размеру объекта)
кластеризацией центров треугольников (k-средних с фиксированным зерном, чтобы куски были одни и те
же между запусками). Каждый кусок — отдельная сетка из своих треугольников с исходными UV и
нормалями, закрытая «толщиной»: края куска выдавливаются внутрь на 4–8 % размера объекта, чтобы
в полёте кусок не был пустой скорлупой. Материал — тот же хэндл, что у модели: куски рисуются той же
текстурой и не плодят материалы. У куска запоминаются центр в осях модели и габариты.

Альтернативы: процедурное разбиение Вороного объёма (дорого и нужны внутренние грани с текстурой,
которой нет); готовые куски из Blender (ещё по файлу на модель, ручная работа на каждую новую
модель). Нарезка сетки даёт «части того, что разломалось» автоматически для любой модели.

### Библиотека форм для примитивов и мелочи
Startup-система строит по 4 варианта каждой формы: глыба (выпуклая оболочка случайных точек),
осколок кристалла (сужающаяся пятигранная призма), кусок штукатурки (неровная плита), черепица
(тонкая изогнутая плитка), доска (брусок со скошенным торцом), лист металла (тонкий гнутый лист),
ком земли (сплюснутая глыба), пучок листвы (несколько скрещенных плоскостей), крошка. Цвет — из
модели, если она есть (средний цвет её текстуры по классу), иначе нынешние палитры.

### `SpawnDebris` получает форму вместо куба
Поле `shape`: `Cube` (как сейчас, для совместимости), `Piece { model, index }` (кусок модели) или
`Form { kind, variant }` (библиотека). Материал хранится хэндлом рядом с цветом. Посадка считает
половину высоты по габаритам формы с учётом поворота, а не `scale.y * 0.5`. В `DebrisStore`
хранится форма, а не только цвет, чтобы пересоздать тот же кусок.

### Источники переводятся по одному
Дома: обрушение берёт куски модели дома, сортирует по высоте центра — верхние падают как крыша,
нижние валятся наружу как стены, плюс доски, черепица и крошка; руины — нижние куски, оставленные
на фундаменте. Предметы, враги, поезда — свои куски при гибели; у врагов и Службы обломки появляются
независимо от мощности взрыва гибели; колёса — отдельные модели `enemy_wheel`, катятся и падают.
`shatter()` берёт сетки из потомков сцены модели, а не прямых детей.

### Пыль — частицами `bevy_hanabi`
Шлейф за крупным обломком — частицы на время полёта; облачко при первом касании земли. Без
обломков-сущностей для пыли.

### Показ в каталоге
Для каждой модели с нарезкой каталог получает вид «взрыв» — модель и её куски, разнесённые от
центра. Куски выгружаются в glb скриптом в `scripts/` той же нарезкой, что и в игре (общее зерно).

## Risks / Trade-offs

- [Нарезка даёт рваные «скорлупки» на тонких местах (балкон, антенна)] → толщина по габариту куска,
  мелкие куски сливаются с соседними, порог минимального размера.
- [Много кусков после сноса посёлка] → кусков на дом не больше ~24, мелкие без тени, общий предел
  лежащих обломков с удалением мелких и дальних, замер FPS на M2 в задаче.
- [Куски модели в руинах не совпадают с её фундаментом при растяжке `house_fit`] → куски создаются
  дочерними к той же растяжке, что и модель.
- [Нарезка в первом кадре после загрузки — рывок] → нарезка одной модели за кадр, результат в ресурсе.
- [Различие кусков между игрой и каталогом] → одно зерно и один алгоритм, скрипт каталога читает
  те же параметры.
