## 1. Транспорт

- [ ] 1.1 Зависимости под `cfg(not(target_arch = "wasm32"))` в `Cargo.toml` и `android/Cargo.toml`: `iroh` 1.x (`default-features = false`, `tls-ring`, `portmapper`; без `metrics`), `tokio`, `crossbeam-channel`, `postcard` 1.x; `INTERNET` в манифесте Android. Замер размера APK и iOS-приложения до и после. Проверка: `cargo build`, `scripts/build-android.sh --abi=arm64-v8a` и `scripts/build-ios.sh --sim` собираются, размер — в этот файл
- [ ] 1.2 `src/net/link.rs`: поток с `tokio`, endpoint iroh без ретранслятора и без обнаружения n0 (`RelayMode::Disabled`), ресурс `NetLink` с каналами «Управление», «События» и датаграммами, заголовок `{ kind, epoch, seq }`. Проверка: тест — два endpoint на localhost обмениваются пакетом по всем трём каналам, старая эпоха отбрасывается
- [ ] 1.3 Имитация плохой сети в `NetLink`: задержка, джиттер, перестановка и потери по `profile::debug_value("net_sim")`, профили `wifi`, `mobile`, `bad` и `rtt,джиттер,потери`. Проверка: тест — при `bad` средняя задержка около 125 мс в одну сторону, потери 5 % ± 1 % на 10 000 пакетов
- [ ] 1.4 `src/net/protocol.rs` без зависимостей от Bevy: `Hello { protocol, name, device_class }`, `Welcome { player, session_token }`, `Refused { reason }`, `Lobby`, `StartRun`, `RoverState`, `ForceCorrection`, `Snapshot`, `Event`, `Checkpoint`, `Rejoin`; `postcard`. Проверка: тест сериализации туда-обратно
- [ ] 1.5 `NetRole`, флаги `--host` (отладочный ключ из постоянной строки, адрес узла в лог) и `--join=адрес:порт`, рукопожатие с проверкой `PROTOCOL`. Проверка: две копии на localhost — в логе «подключён игрок 1»; копия с другим `PROTOCOL` получает «Другая версия игры»

## 2. Лобби

- [ ] 2.2 `StartRun { seed, difficulty, players }`: у всех `RunWorld::start_run` с сидом хоста, `PlayerCount`, у клиента `LocalPlayer` — свой номер. Проверка: две копии — забег начинается у обеих, рельеф на снимках одинаковый

## 3. Роли в кадре

- [ ] 3.1 Набор `GameSet::SimulationShared` после `Simulation`; в него — `push_vehicles_out`, полёт снарядов и ракет (урон — только под `authority()`), `subsidence::settle`, течение лавы. Проверка: `cargo test`; одиночная игра без изменений (`--bench=60` — тот же FPS)
- [ ] 3.2 Условие `authority()` на `Simulation`, системы урона в `Damage`, `ApplyDamage`, `Death`, `Cleanup`; `dig_craters` и читатели рельефа после него — у всех. Проверка: `cargo test`; одиночная игра без изменений
- [ ] 3.3 Клиент ведёт свой луноход сам и шлёт `RoverState` 30 Гц (`seq`, время, `shot_seq` с хвостом трёх). Хост отбрасывает старые `seq`, ограничивает сдвиг по прошедшему времени, пишет `PlayerInput` удалённого лунохода. Проверка: тест — переставленные пакеты не двигают луноход назад, прыжок обрезается; две копии — луноход клиента ездит у хоста
- [ ] 3.4 `ForceCorrection` от хоста по «Управлению» и плавное вливание в скорость за 150 мс у владельца. Проверка: взрыв у лунохода клиента — луноход отлетает у обоих без телепорта
- [ ] 3.5 Пауза при `NetRole != Offline` не останавливает время, ввод своего лунохода обнуляется. Проверка: пауза у клиента — у хоста враги едут

## 4. Снимки

- [ ] 4.1 `NetId` (старшие 8 бит — эпоха), `Replicated { kind }`, раздача номеров у хоста для луноходов, врагов, боссов, перехватчиков, Службы, вагонов, ящиков, аптечек, жителей. Проверка: `cargo build`, в логе хоста число реплицируемых
- [ ] 4.2 Сбор снимка 20 Гц с номером тика хоста и квантованием; нарезка на самодостаточные датаграммы до 1100 байт. Проверка: тест — снимок 90 сущностей туда-обратно с ошибкой меньше 5 см; потеря одной части не мешает применить остальные
- [ ] 4.3 Интерес по клиенту: до 180 м — каждый снимок, 180–350 м — 4 Гц, дальше — нет. Проверка: тест фильтра; счётчик байт снимков в лог раз в 10 с
- [ ] 4.4 Буфер интерполяции по времени хоста с адаптивной задержкой 100–250 мс по джиттеру, экстраполяция до 200 мс, гашение ошибки за 100–200 мс, телепорт при ошибке больше 4 м. Проверка: тест буфера (переставленные и потерянные снимки, скачок джиттера); две копии с `net_sim=bad` — враги у клиента едут ровно
- [ ] 4.5 Здоровье, подбитие, горение и «стреляет» из снимка у клиента; HUD своего лунохода — от здоровья хоста; трассеры чужого пулемёта по флагу. Проверка: две копии — урон по клиенту виден на его полосе, очередь хоста видна у клиента

## 5. События

- [ ] 5.1 `replicate_message::<T>()`: поток «События» с `event_id`, отправка у хоста в конце кадра, запись у клиента в начале кадра. Проверка: тест с фиктивным сообщением
- [ ] 5.2 Появление и исчезновение реплицируемых: спавн у клиента теми же функциями, связь `NetId → Entity`. Проверка: две копии — враги волны появляются у клиента с обликом
- [ ] 5.3 Свой выстрел сразу: у стреляющего клиента вспышка, звук, отдача и снаряд-призрак `Ghost { shot_seq }`; хост рассылает выстрел с `(луноход, shot_seq)`, клиент переводит призрак на траекторию хоста без второго снаряда. Проверка: `net_sim=bad` — мортира клиента стреляет в кадр нажатия, снаряд один, кратер у обоих в одном месте
- [ ] 5.4 Выстрелы хоста и врагов (`FireShell`, `FireRocket`, `FireLaser`) и `Explosion`: у клиента облик и звук без урона, `dig_craters` роет по `Explosion`. Проверка: тест — высоты участка у хоста и клиента совпадают после серии кратеров
- [ ] 5.5 Лазерная траншея — новое сообщение `LaserCut`, клиент режет `cut_trench`; `TunnelOpened` — открытие без порога толщины. Проверка: тест — высоты после траншеи совпадают; две копии — обвал тоннеля у обоих
- [ ] 5.6 Лава у клиента: источники по `CrustBreached`, течение своё, поправка ячеек раз в секунду по «Управлению», жжение — только у хоста. Проверка: сцена `lava_slope` двумя копиями — расхождение толщины после поправки меньше 1 см
- [ ] 5.7 Обход остальных `add_run_message`: переслать первичные причины видимого и слышимого (`Died`, `WaveStarted`, `TrainDerailed`, `ResidentDied`, `ServiceArrived`, `MedkitPicked`, `WeaponPicked`, `UpgradePicked`, `VoiceCue`…), не пересылать `TerrainChanged`, `Damage`, `Rammed`, пули и сколы; список с решением по каждому — в комментарии модуля. Проверка: две копии — волна, тревога и реплики штаба звучат у клиента

## 6. Ключи мира

- [ ] 6.1 `RegionHouses`: хост шлёт дома региона, когда тот впервые попадает в подгрузку любого лунохода; клиент ставит дома и тропинки по нему, а не своей отбраковкой. Проверка: тест — дома и тропинки клиента совпадают с хостом при двух порядках подгрузки
- [ ] 6.2 Разрушения по `HouseId`, `LinkKey` и ключам деревьев и камней: хост шлёт, клиент ставит руины сразу и при поздней подгрузке участка. Проверка: две копии — дом, разрушенный у хоста, у клиента в руинах, и после отъезда и возврата тоже

## 7. Переподключение и выход

- [ ] 7.1 Контрольная точка раз в 2 с по «Управлению» (тик, `SurvivalTime`, угроза, таймеры волн, тревога, поезда, здоровье и флаги каждого `NetId`) и журнал постоянных изменений у хоста и клиентов. Проверка: тест — точка 90 сущностей меньше 1 КБ; размер журнала за `--bench=180` в лог
- [ ] 7.2 Обрыв клиента: «Связь потеряна…» через 1,5 с, у хоста его луноход стоит и не выбирается врагами; `AppLifecycle::Suspended` — тот же обрыв. Проверка: две копии, `net_sim=0,0,100` на 5 с — надпись у клиента, враги у хоста его не атакуют
- [ ] 7.3 `Rejoin { player, session_token, last_event_id }`: хост досылает события из журнала, контрольную точку и полный снимок; клиент применяет под занавесом без звука и частиц. Проверка: две копии — клиент отключён на 10 с, хост разрушил дом; после возврата дом у клиента в руинах, луноход и здоровье прежние
- [ ] 7.4 Через 30 с без связи — луноход убирается с надписью «<имя> вышел»; при прямом подключении клиент без хоста 5 с — экран «Хост вышел» и меню. Проверка: две копии, закрыть клиента, затем хоста
