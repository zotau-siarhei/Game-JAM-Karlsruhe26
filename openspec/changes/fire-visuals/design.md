# Design

## Context

Огонь сейчас (полный обзор — в истории этого изменения):

- кроны (`props.rs`), горящие обломки (`debris.rs`, не больше 12), руины (`collapse.rs`, по 3 на
  дом), огонь лавы (`lava.rs`) — сферы с `unlit` материалом, масштаб пульсирует синусом; пламя
  обломка — ребёнок кувыркающегося куба и наследует его неравномерный масштаб и вращение;
- термобарика (`rockets.rs`) — 6 горящих кубов-обломков, своей картинки у зоны урона нет, обломки
  горят 3–6 с при уроне 3 с;
- поезд (`trains.rs`) — только `PointLight` на вагон, без предела;
- сопло ракеты, след капсулы, вспышка мортиры — сфера, брусок и сфера `unlit`;
- огненный шар взрыва (`explosion_fx.rs`) — 3–5 сфер с новым материалом на каждый взрыв и цветом из
  градиента не ярче 1,0; искры взрыва — `bevy_hanabi` с HDR-градиентом до 4,0 (единственное, что
  светится);
- дым лавы и ровера — сферы и частицы без прозрачности на исходе.

Камера: HDR, `TonyMcMapface`, `Bloom::NATURAL` на среднем и высоком качестве, без MSAA на среднем.
Собственных шейдеров и текстур частиц в проекте нет. Цель — MacBook Air M2.

## Goals / Non-Goals

**Goals:**
- Один модуль огня, которым горит всё; вид задаётся размером и силой.
- Красивое пламя без текстур и тяжёлой симуляции, с ценой не выше нынешней.
- Свечение через HDR-цвет, предел светящих огней, учёт ступени качества.

**Non-Goals:**
- Распространение огня с предмета на предмет и новые источники урона.
- Объёмный огонь (raymarching) и тепловое марево (экранное искажение) — дорого для M2, может быть
  отдельным изменением.
- Новые звуки огня.

## Decisions

### Пламя — карточки с шейдером шума, а не флипбук и не объём
Пламя — 1–3 вертикальные карточки (квад), повёрнутые к камере только вокруг вертикали (камера
смотрит сверху под углом, поэтому пара скрещённых карточек на крупном огне не даёт видеть ребро).
Материал — свой `Material` с WGSL: два слоя шума (fbm), сдвигаемые вверх с разной скоростью,
искажают маску формы «капли»; эрозия маски по параметру силы даёт рваный край и угасание; цвет — по
рампе «белое ядро → жёлтый → оранжевый → тёмно-красный → прозрачный», значения ядра выше 1 для
свечения; смешивание аддитивное для ядра и с прозрачностью для краёв. Фаза шума — из мировой
позиции, поэтому соседние огни не движутся в такт без отдельного материала на огонь.

Альтернативы:
- флипбук (заранее отрендеренная анимация огня в текстуре-атласе) — реалистичнее, но нужна симуляция
  в Blender и память под атлас, огни выглядят одинаково и повторяются по циклу;
- объёмный огонь лучом (raymarching по 3D-шуму) — лучший вид сверху, но несколько шагов на пиксель
  на каждом огне дорого для M2;
- частицы `bevy_hanabi` без текстуры (как сейчас у искр) — круглые точки, пламя из них не выходит.

Шумовой шейдер на карточке — приём из стилизованных игр (эрозия маски шумом, бегущим вверх), даёт
живое пламя за одну выборку шума на пиксель и не требует ассетов.

### Искры и дым — `bevy_hanabi`
Искры: аддитивные мелкие частицы, ускорение вверх, турбулентность, затухание, HDR-градиент. Дым:
частицы с мягкой круглой текстурой (процедурная, 64×64, создаётся при запуске), смешивание с
прозрачностью, рост и затухание прозрачности, снос ветром. Одни `EffectAsset` на весь огонь,
экземпляру задаются размер и сила через свойства, как у взрывов.

### Свет — общий пул
Огонь регистрируется в ресурсе; каждый кадр свет получают N ближайших к камере огней (4 / 6 / 8
по ступени качества), интенсивность мерцает шумом по времени. Отдельный `PointLight` на огонь не
создаётся.

### API модуля
Компонент `Fire { size, intensity, lifetime, smoke_after }` на сущности-носителе. Модуль сам ставит
карточки, искры, дым и регистрирует свет; карточки — не дети носителя по вращению: они следуют за
позицией, но стоят вертикально и не наследуют масштаб (решает пламя на кувыркающемся обломке).
Дальние огни (дальше ~60 м) теряют искры и дым; число частиц умножается на долю ступени качества.

### Свечение старых материалов
Пока источники переводятся на модуль, у нынешних `unlit` огненных материалов цвет задаётся в
`base_color` с HDR-значениями выше 1 (в Bevy `unlit` выводит только `base_color`). Это первая
задача: огонь начинает светиться сразу.

## Risks / Trade-offs

- [Пользовательский шейдер в Bevy 0.20 — первый в проекте, API материалов меняется между версиями]
  → сверять с docs.rs/bevy/0.20.1, начать с минимального материала и проверить на снимке.
- [Прозрачные карточки и сортировка: огонь перед дымом мерцает] → ядро аддитивное (не требует
  сортировки), дым рисуется с прозрачностью и не пишет глубину.
- [Много огней после авиаудара] → предел видимых огней, дальние без частиц, свет из пула, замер FPS.
- [Карточка видна ребром при взгляде сверху] → для крупных огней две скрещённые карточки, наклон к
  камере по вертикали ограничен.
