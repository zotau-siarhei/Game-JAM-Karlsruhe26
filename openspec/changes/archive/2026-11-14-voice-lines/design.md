## Context

Реплики штаба генерируются в ElevenLabs заранее и лежат в игре готовыми файлами. ElevenLabs
по умолчанию отдаёт MP3. Событий, на которые реплики звучат, в игре ещё нет: ядро, кратеры
и бой только описаны. Сборка только нативная.

## Goals / Non-Goals

**Goals:**
- Один список реплик, который читают игра и страница предпросмотра.
- Добавление реплики без правки кода: строка в списке и файл рядом.
- Игра запускается и работает, пока реплики не озвучены.

**Non-Goals:**
- События игры, которые запускают реплики: их добавляют изменения с самими механиками.
- Очередь реплик, приоритеты, субтитры, громкость.
- Обращение к ElevenLabs из игры.

## Decisions

### Список — JSON в `assets/voice/lines.json`
Поля реплики: `id`, `event` (описание события), `text`, `file`. JSON читается браузером без
библиотек, поэтому страница предпросмотра и игра используют один файл. Альтернатива — RON,
привычный для Bevy: браузер его не читает.

### Список читается с диска при запуске, звуки — через `AssetServer`
`lines.json` читается обычным чтением файла из каталога ассетов Bevy и разбирается `serde_json`.
Альтернатива — свой загрузчик ассета: больше кода, а асинхронная загрузка списка здесь не нужна.
Перед загрузкой звука проверяется, что файл есть, чтобы отсутствие реплик давало одно
предупреждение в логе, а не ошибку загрузки на каждую.

### Воспроизведение — сообщение `PlayVoice(id)`
Механики отправляют сообщение и не знают про звук. Система голоса создаёт сущность
с `AudioPlayer`, которая удаляется после окончания. Новая реплика обрывает звучащую:
одновременно говорит один голос. Альтернатива — очередь: реплика о событии прозвучала бы
с опозданием, когда событие уже прошло.

### Предпросмотр — одна статическая страница рядом со списком
`preview.html` загружает `lines.json` через `fetch` и проигрывает файлы тегом `Audio`. Браузер
не даёт читать JSON со страницы, открытой как файл, поэтому страница открывается через
`python3 -m http.server`. На случай открытия файлом есть выбор `lines.json` вручную.

## Risks / Trade-offs

- [Опечатка в идентификаторе в коде] → предупреждение в логе при попытке проиграть реплику.
- [Реплики обрывают друг друга при частых событиях] → частоту ограничивает тот, кто отправляет
  сообщение; очередь добавляется позже, если понадобится.
