## Context

Своего сервера пока нет (`room-server` не начат). Игра собирается нативно (компьютеры, Android без
Gradle и DEX, iOS) и в браузер. На Android игра — `NativeActivity` с `hasCode="false"`, поэтому
SDK Google на Java (Credential Manager, Play Games Services) недоступны без новой системы сборки.

## Goals / Non-Goals

**Goals:**
- Вход только через Google, только из «Мультиплеера», одиночная игра без сети.
- Одна схема входа на всех нативных платформах, без обратной ссылки в приложение и без своего домена.
- Идентификатор игрока, который потом проверит сервер: `sub` Google; токен обновления хранится,
  чтобы позже получать свежий `id_token`.

**Non-Goals:**
- Сервер, проверка `id_token` на сервере, сама сетевая игра — следующие изменения ветки.
- Вход в браузерной сборке (там нет и сети).
- Открытие браузера и копирование кода на iOS: там код и адрес просто показываются.
- Другие провайдеры, Game Center, анонимные аккаунты.

## Decisions

### Вход по коду устройства
`POST https://oauth2.googleapis.com/device/code` с `scope=openid email profile` даёт `user_code`,
`verification_url`, `device_code`, `interval`, `expires_in`. Игра показывает код, копирует его и
открывает адрес, затем раз в `interval` секунд спрашивает `https://oauth2.googleapis.com/token`
(`grant_type=urn:ietf:params:oauth:grant-type:device_code`): `authorization_pending` — ждать,
`slow_down` — интервал +5 с, `access_denied` и `expired_token` — ошибка на экране. Успех даёт
`id_token` и `refresh_token`.
*Альтернативы:*
- Перенаправление на `127.0.0.1` (клиент «Desktop»): удобнее на компьютере, но на Android свёрнутую
  игру через 10 с замораживает система (cached apps freezer), и Chrome висит на возврате, а iOS
  приостанавливает приложение в фоне.
- Credential Manager или Play Games на Android: нужен DEX и Gradle.
- Своя страница с перенаправлением: нужен домен и HTTPS, а сервера ещё нет.

### Клиент Google и секрет
Тип клиента — «TVs and Limited Input devices»: Google требует для него `client_secret`, но для
устанавливаемых приложений секретом его не считает. ID и секрет берутся из `option_env!` при сборке
(`SPACE_GUARD_GOOGLE_CLIENT_ID`, `SPACE_GUARD_GOOGLE_CLIENT_SECRET`), на компьютере их можно
переопределить переменными окружения при запуске. Для разработки значения лежат в `google-auth.txt` в
корне основной копии (строки `export ИМЯ='значение'`, файл в `.gitignore`): на компьютере игра читает его
сама, ища от `CARGO_MANIFEST_DIR` и текущего каталога вверх (так его видят и worktree), а перед сборкой для
телефона его подключают `source`. В публичный репозиторий значения не кладутся, чтобы их не подхватил сканер
секретов GitHub. Без них экран мультиплеера пишет, что вход в этой сборке не настроен.

### HTTP — `ureq` в своём потоке
`ureq` 3 без gzip, TLS — rustls с ring и корнями webpki-roots: одинаково на всех нативных
платформах, без системного хранилища сертификатов. Поток входа — обычный `std::thread`. Наружу он
пишет состояние в общий слот `Arc<Mutex<Option<SignIn>>>`, а система `pump` переносит его в ресурс
`SignIn`, на изменение которого перерисовывается меню. Отмена — флаг `AtomicBool`, поток проверяет
его каждые 0,25 с. Сетевая ошибка в ожидании не прерывает вход: телефон мог сменить сеть, следующий
запрос повторится; первая же ошибка запроса кода — ошибка на экране.

### `id_token` без проверки подписи на устройстве
Токен приходит прямо от `oauth2.googleapis.com` по TLS, поэтому игра лишь разбирает полезную часть
(base64url → JSON: `sub`, `email`, `name`). Подпись проверит сервер.

### Хранение
`account.json` рядом с `settings.json` (каталог `records::records_path()`): `id`, `name`, `email`,
`refresh_token`. Запись через временный файл, на Unix — права 0600. В автокопию Android не входит:
`backup_rules.xml` перечисляет только рекорды. При запуске файл читается без сети: игрок сразу
«вошёл». «Выйти» — `POST https://oauth2.googleapis.com/revoke` в фоне и удаление файла.

### Открыть адрес и скопировать код
- Android: JNI в потоке интерфейса Java — `ClipboardManager.setPrimaryClip` и
  `Intent.ACTION_VIEW` с `FLAG_ACTIVITY_NEW_TASK`.
- macOS: `pbcopy`, `open`; Windows: `clip`, `cmd /C start`; Linux: `wl-copy` или `xclip`, `xdg-open`.
- iOS: ничего, адрес и код на экране.

### Меню
Пункты `Item::Single` (бывший `Play`) и `Item::Online` первыми строками главного меню. Страница
`MenuPage::Online` рисуется по `SignIn`: «Войти через Google», «Открыть браузер», «Отмена»,
«Повторить», «Выйти», «Назад». Esc на странице во время входа отменяет вход.

## Risks / Trade-offs

- [Код устройства на телефоне — лишний шаг: вставить код в браузере] → Код уже в буфере обмена,
  страница открывается сама; на Android 13+ система показывает «Скопировано».
- [Google может спросить на проверке приложения, зачем клиент для телевизоров на телефоне] → Для
  scope `openid email profile` проверка не нужна; в режиме «Testing» войти могут только тестовые
  пользователи (до 100), токен обновления живёт 7 дней — для разработки этого хватает.
- [ring для Android собирается C-компилятором NDK] → Как и `meshopt`: скрипт сборки уже задаёт
  компилятор.
- [Секрет клиента в бинарнике] → Так у всех устанавливаемых приложений; утечка даёт лишь право
  показывать экран входа от имени игры, доступа к аккаунтам не даёт.
