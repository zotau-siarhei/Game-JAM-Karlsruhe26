**Отладочные ручки сейчас разные на разных системах:** `SPACE_GUARD_OFF`, `SPACE_GUARD_DETAIL`,
`SPACE_GUARD_MOBILE` на компьютере; `debug.spaceguard.{quality,density,shadows,detail,off,compute,sync,
novsync,perf}` на Android; `?quality=` в браузере; на iOS — только окружение запуска, и скрипт его не
передаёт.

**Что известно о железе (исследование, источники — в конце):**
- GPU Apple — плиточные (TBDR): перерисовка непрозрачного почти бесплатна (HSR), MSAA разрешается в
  памяти плитки и дёшев по вычислениям; дорога пропускная способность памяти: HDR-цель `Rgba16Float`
  (8 байт на пиксель), каждый проход bloom, лишние полноэкранные проходы. Поэтому на iPhone главное —
  разрешение кадра и число проходов, а не MSAA.
- iPhone 15 Pro Max в долгой нагрузке держит 60–76 % пиковой мощности GPU, троттлинг до 40 %.
  Без ключа `CADisableMinimumFrameDurationOnPhone` в `Info.plist` iPhone и так ограничен 60 Гц;
  в режиме энергосбережения ProMotion тоже 60.
- Память на iPhone официально не задана; наблюдаемый потолок процесса на 8 ГБ — около 6 ГБ, надёжный
  бюджет 2–3 ГБ; верный путь — `os_proc_available_memory()` во время игры.
- Кэша конвейеров на Metal в wgpu нет (только Vulkan) — единственная защита от рывков компиляции
  остаётся прогрев (`prewarm.rs`).
- Unreal (Device Profiles с `BaseProfileName`), Unity (матрица ступеней × платформ) и Godot (feature
  tags `.mobile`, `.web_ios`) сходятся в одном: база → платформа → класс устройства → выбор игрока →
  отладка, данные в файле, поздний слой задаёт только отличия.

## Goals / Non-Goals

**Goals:**
- Одно место, где видно и меняется любое ограничение любой платформы.
- Профиль iOS (iPhone и iPad отдельно) с облегчениями телефона и с учётом плиточных GPU Apple.
- Одни и те же имена отладочных переопределений на всех системах.
- Перенос без изменения поведения на macOS, Linux, Windows, в браузере и на Android.

**Non-Goals:**
- Автоматический подбор ступени по замеру кадров и таблица устройств по модели или GPU — следующим
  изменением; здесь только классы устройств (телефон, планшет, компьютер).
- Сохранение настроек в браузере и на Windows (там сейчас нет каталога данных) — отдельная задача.
- Переход winit на сцены UIKit (UIScene) — в изменении `ios-build`.
- Новые эффекты и новые ступени качества.

## Decisions

### 1. Данные — `assets/platform/profiles.json`, вшитый через `include_str!`
JSON, как остальные списки проекта, разбор `serde_json`. Файл вшивается в исполняемый файл: на
Android ассеты лежат в APK, в браузере — по сети, а профиль нужен до загрузки ассетов (окно, пулы
потоков, режим конвейеров). Альтернатива — RON или `const` в коде: RON — новая зависимость, `const`
не даёт наследования и смотреть числа всех платформ рядом.

### 2. Наследование и ступени
```json
{
  "base":       { "debris": { "max_resting": 1500, "shadow_min_size": 0.8 },
                  "render": { "density": [null, null, null], "msaa_high": 4,
                              "shadows": [[512,1,40],[1024,2,70],[2048,3,110]] } },
  "desktop":    { "parent": "base" },
  "macos":      { "parent": "desktop" }, "linux": { "parent": "desktop" }, "windows": { "parent": "desktop" },
  "web":        { "parent": "base", "menu": { "quit": false } },
  "web-desktop": { "parent": "web" },
  "web-mobile": { "parent": "web", "debris": { "max_resting": 600, "shadow_min_size": 1.2 } },
  "mobile":     { "parent": "base", "render": { "density": [1.25, 1.5, 2.0] }, "...": "..." },
  "android":    { "parent": "mobile", "render": { "msaa_high": 1 } },
  "ios-phone":  { "parent": "mobile" },
  "ios-tablet": { "parent": "ios-phone", "class": "tablet" }
}
```
Значение со ступенями — массив `[low, medium, high]`, иначе одно значение на все ступени. Слияние —
глубокое по объектам JSON (`serde_json::Value`), затем разбор в `PlatformProfile` со всеми полями
обязательными: забытое поле — ошибка при запуске тестов, а не тихое значение по умолчанию.

### 3. Ресурс и слои
`src/profile.rs`: `ProfilePlugin` до остальных плагинов определяет платформу и класс устройства,
собирает профиль и кладёт ресурс `PlatformProfile`. Ступень качества берётся из профиля при
обращении: `profile.shadows(quality)`, `profile.density(quality)` — модули по-прежнему следят за
`Quality`, отдельного пересчёта нет. Порядок слоёв: файл (база → платформа → класс) → ступень →
`Settings` игрока → переопределения (решение 4).

Класс устройства: iOS — `UIDevice.userInterfaceIdiom` (телефон/планшет), браузер —
`window.spaceGuardMobile` страницы, Android — телефон (планшеты Android пока тем же профилем).

### 4. Переопределения — одно имя, разные транспорты
Ключ — путь в профиле: `render.density`, `debris.max_resting`. Транспорт:
- компьютер и iOS — `SPACE_GUARD_RENDER_DENSITY=1.0` (путь в верхнем регистре, точка → `_`);
- Android — `adb shell setprop debug.spaceguard.render.density 1.0`;
- браузер — `?render.density=1.0`.
Старые имена (`debug.spaceguard.density`, `shadows`, `detail`, `quality`, `off`, `SPACE_GUARD_OFF`,
`SPACE_GUARD_DETAIL`, `SPACE_GUARD_MOBILE`, `?quality=`) остаются синонимами: на них завязаны записи
в CLAUDE.md и привычные замеры. Все действующие переопределения — одной строкой в лог при запуске.
`build-ios.sh` получает `--env КЛЮЧ=значение`, который передаётся в `devicectl process launch`.

### 5. Что идёт в профиль, а что остаётся условием платформы
В профиль — всё, что про мощность и память: плотность, тени, MSAA, bloom, предел кадров, обломки,
огни и вспышки, упрощение моделей, тени-силуэты, размер текстур, прогрев (кадров до старта,
ждать ли конвейеры), пулы потоков, ступень и ввод по умолчанию, пункт «Выход».
Условием платформы остаются обходы драйверов и систем: замена выборки тени точечных источников и
отключение GPU preprocessing (Adreno), перезапуск после DeviceLost, защита от повторного запуска
NativeActivity, правки шейдеров WebKit в `index.html`, частицы выключены в симуляторе iOS,
версия SDK в `build-ios.sh`.

### 6. Значения профиля iOS (стартовые, уточняются замером)
| | iPhone | iPad | основание |
|---|---|---|---|
| плотность low/med/high | 1,25 / 1,5 / 2 | 1 / 1,5 / 2 | как Android; исследование советует ~1,5 |
| тени med / high | 1/60 (1024), 2/70 (2048) | как iPhone | как Android; карта 2048 — мобильный стандарт Godot |
| MSAA на high | 4× | 4× | на TBDR разрешается в плитке |
| bloom | med, high | так же | при замере проверить цену проходов |
| предел кадров | 60 | 60 (ProMotion — флаг профиля) | троттлинг, батарея; `Info.plist` без ключа 120 Гц |
| обломков / тень от | 600 / 1,2 | как iPhone | класс не отличает iPad 9 (A13) от iPad Pro (M) — числа под слабый |
| огней / вспышек | 2/3/4, 3 | как iPhone | |
| упрощение моделей, силуэты | да | да | meshopt уже собирается под iOS |
| текстуры | 1024 при сборке | 1024 при сборке | меньше `.app` и быстрее загрузка |
| прогрев | 3 кадра до старта, конвейеры не ждать | так же | Metal компилирует асинхронно без зависаний |
| ступень по умолчанию | low | medium | |

### 7. iOS: жизненный цикл и предел кадров
Пауза звука в фоне — по `bevy::app::AppLifecycle` (`WillSuspend`/`WillResume`, их шлёт winit),
как на Android, общим кодом вместо `android.rs`. Предел кадров: на iPhone без ключа
`CADisableMinimumFrameDurationOnPhone` система сама не даёт больше 60 Гц — ничего делать не нужно.
iPad с ProMotion отдаёт 120 Гц, поэтому поле профиля `frame_limit` выполняет простой ограничитель:
система в `Last` досыпает до длительности кадра по `Instant` (как `bevy_framepace`, без новой
зависимости). На компьютере и в браузере `frame_limit` пуст. Слой «нагрев и энергосбережение» (`ProcessInfo.thermalState`, `isLowPowerModeEnabled`) — понижение
плотности на шаг при `.serious` — входит последней задачей, его можно отложить без вреда для
остального.

### 8. Что выяснилось при проверке
- Отладочная ступень (`quality`) не должна попадать в файл настроек игрока: в игре и меню она
  действует, а в файл пишется прежняя (`settings::ForcedQuality`).
- Неверное значение переопределения не роняет игру: каждое проверяется разбором профиля,
  отклонённое — предупреждение в лог.
- iPad получает числа iPhone, кроме плотности 1/1,5/2, ступени medium и предела 60 кадров: класс
  устройства не отличает iPad 9 (A13, 3 ГБ) от iPad Pro на M-серии. Таблица моделей — следующим изменением.
- На iOS лог пишется ещё и в файл песочницы: с телефона системный лог без sudo не достать.

## Risks / Trade-offs

- [Перенос меняет поведение незаметно] → тест, который собирает профили macOS, linux, windows, web,
  web-mobile и android и сверяет каждое поле с числами из таблицы Context.
- [Профиль собирается до `Settings` и окна] → `ProfilePlugin` не зависит от ресурсов Bevy, только от
  платформы и переопределений; ступень читается позже.
- [Синонимы старых ручек множат имена] → таблица синонимов в одном месте `profile.rs`, через
  месяц — удалить.
- [iPad без проверки на устройстве] → значения iPad — стартовые; проверка в симуляторе iPad
  (кадр и меню), замер — когда будет iPad.
- [UIScene на iOS 27] → не этого изменения: сборка с версией SDK 18 работает; при переходе на SDK 27
  нужен winit с поддержкой сцен (PR rust-windowing/winit#4723, ветка `uiscene-minimal-v0.30`).

## Migration Plan

1. Профили и ресурс без потребителей, тест равенства с сегодняшними числами.
2. Модули по одному переходят на профиль; после каждого — `cargo test` и снимок `SPACE_GUARD_SHOT`
   на Mac, APK на эмуляторе для Android.
3. Профиль iOS включается последним; откат — профиль `ios-phone` с `parent: base`.
