## Context

Мотивация — в `proposal.md`, требования — в `specs/rooms/spec.md`. Что уже будет к этому моменту
по `net-coop`:

- транспорт `iroh` в отдельном потоке с `tokio`, ресурс `NetLink`: каналы «Управление», «События»,
  датаграммы, заголовок `{ kind, epoch, seq }`;
- протокол в `src/net/protocol.rs` (`postcard`), версия `PROTOCOL`;
- роли `NetRole`, лобби `GameState::Lobby`, прямое подключение `--host` и `--join`;
- контрольная точка раз в 2 с, журнал постоянных изменений у хоста и клиентов, `Rejoin`;
- `NetId` с эпохой в старших битах.

Сейчас клиент подключается прямо к хосту по адресу. Через NAT телефона и мобильного оператора
(CGNAT) так часто не достучаться, а уход хоста кончает забег у всех. Решения взяты из исследования
«Сетевая игра Space Guard»: «сначала ретранслятор, прямой путь в фоне» (как DERP у Tailscale и iroh)
и миграция хоста с арбитром эпох.

## Goals / Non-Goals

**Goals:**
- Игроки соединяются при любом роутере и мобильном интернете, в большинстве пар — напрямую.
- Нагрузка на VPS — только комнаты и пакеты пар, которым прямой путь не удался.
- Уход хоста (звонок, свёрнутое приложение, потеря сети) не кончает забег: роль переходит к другому
  игроку за 0,5–1,5 с.
- Ни домена, ни сертификатов Let's Encrypt.
- Сервер не видит содержимого забега и не хранит адресов.

**Non-Goals:**
- Аккаунты, друзья, ссылки-приглашения (пользователь выбрал «только код»).
- Браузер-клиент: отдельное изменение позже. Ретранслятор iroh его уже поддерживает. Понадобится
  сертификат, которому верит браузер, то есть домен.
- Несколько серверов и регионы: один VPS в Европе.
- Вход нового игрока посреди забега: вернуться может только тот, кто в нём был.
- «Умный ретранслятор» с журналом и снимками на сервере: пакеты зашифрованы из конца в конец,
  журнал держат игроки.

## Decisions

### Сервер — отдельный пакет `server/`, один процесс на две службы
Бинарник `space_guard_server`, свой `Cargo.toml` рядом с `android/`. В `cargo build` игры он не
входит. Внутри два сервиса на одном `tokio`:
- **служба комнат** — endpoint `iroh` с ALPN `space-guard/rooms/1`: коды, быстрая игра, выбор хоста
  и эпохи, переадресация переподключений;
- **ретранслятор** — `iroh-relay` с возможностью `server` библиотекой: HTTPS на TCP 443 (проходит
  любой брандмауэр) и проверка адресов QUIC на UDP 7842.

Протокол общий: сервер подключает `src/net/protocol.rs` через `#[path = "../../src/net/protocol.rs"]`.
Поэтому протокол не зависит от Bevy, только от `serde` и своих `[f32; 3]`.
*Альтернативы:*
- свой ретранслятор на `quinn`, пересылающий кадры по `to`/`from`: весь трафик всегда через VPS, без
  прямого пути, и всё это пришлось бы писать и отлаживать самим;
- cargo workspace — поменял бы общий `target` и сборку APK.

### Соединение игроков: через ретранслятор сразу, напрямую в фоне
- Каждый игрок поднимает endpoint `iroh` со свежим случайным ключом на запуск: постоянного
  идентификатора у устройства нет.
- Карта ретрансляторов — только наш (`RelayMode::Custom`). Обнаружение n0 и публичные ретрансляторы
  выключены.
- Хост сообщает службе комнат свой `EndpointAddr`: ключ, URL ретранслятора, прямые адреса. Клиент
  получает его в `RoomJoined` и соединяется с хостом.
- iroh сразу пускает пакеты через ретранслятор, а в фоне пробивает NAT и, если вышло, переводит
  соединение на прямой путь без обрыва и без участия игры.
- Для `NetLink` и забега всё как при `--join`: те же каналы, тот же протокол. Ретранслятор видит
  только зашифрованные пакеты.

По оценкам Tailscale и iroh, напрямую соединяется 70–90 % пар. Остальные — симметричный NAT
мобильных операторов и корпоративные сети — остаются на ретрансляторе, это около 10–40 мс задержки
по Европе.

### Знакомый сервер без домена
- Служба комнат — узел iroh с постоянным ключом в `/var/lib/space-guard/`. Его `EndpointId` и адрес
  зашиты в игру константами в `src/net/server.rs`, поэтому подменить службу нельзя.
- Ретранслятор работает по TLS с сертификатом на IP-адрес VPS. Сертификат подписан своим корнем
  `rcgen`, корень зашит в игру (`CaTlsConfig::custom_roots`), закрытый ключ корня хранится вне сервера.
- Для локальной отладки — `--server=адрес:порт`, `--server-id=ключ` и `--relay=URL` с корнем из файла.
- Смена ключа службы или корня требует новой версии игры: это приемлемо, ключи меняются редко.

*Альтернатива:* домен и Let's Encrypt (`iroh-relay` умеет ACME сам). Отложено до браузер-клиента.

### Ретранслятор только для своих
`AccessControl` ретранслятора пускает только ключи узлов, которые сейчас состоят в комнате службы.
Чужой узел получает отказ, поэтому VPS не становится бесплатным ретранслятором для других.
`Limits::client_rx` — 2 Мбит/с на соединение. Метрики `iroh-relay` выключены.

### Коды комнат
Алфавит — 30 символов без `O 0 I 1`, длина 4: около 810 тысяч кодов. Код выбирается случайно
среди свободных и показывается заглавными, ввод нечувствителен к регистру. Комната в лобби
живёт 30 минут, во время забега — пока в ней есть хоть один игрок.

### Быстрая игра
Очередь — это просто список открытых комнат быстрой игры по сложности. Игрок попадает в самую
полную из тех, где меньше 4 игроков и забег не начат, иначе создаёт свою и становится хостом.
Таймер автостарта (30 секунд после второго игрока, сразу при четырёх) ведёт хост. Служба помечает
комнату «забег идёт», когда хост прислал `RunStarted`, и больше её не отдаёт.

### Миграция хоста
Служба комнат — арбитр: только она назначает хоста и номер эпохи, поэтому двух хостов сразу быть
не может. Данные для подхвата есть у каждого игрока: мир из сида, журнал постоянных изменений,
последняя контрольная точка (раз в 2 с) и снимки.

1. **Обнаружение.**
   - Хост раз в 0,5 с шлёт службе крошечную датаграмму `Alive`. Нет `Alive` 2 с — хост потерян.
   - Хост, уходящий в фон (`AppLifecycle::Suspended`, звонок — `run::SystemPause`), сразу шлёт
     `YieldHost` с последней контрольной точкой и не ждёт таймаута.
   - Клиенты, потерявшие хоста, сообщают службе `HostLost`, но решает она сама.
2. **Выбор.** Новый хост — по классу устройства из `Hello`: компьютер, потом сильный телефон
   (`android-high`, `ios-*-high`), потом средний, потом слабый. При равенстве — меньший номер игрока.
   Служба увеличивает эпоху и шлёт всем `HostChanged { epoch, player, addr }`.
3. **Подхват.**
   - Новый хост берёт номер последнего события, которое видел сам, применяет контрольную точку
     (время, угроза, таймеры волн, тревога, поезда, здоровье) и ставит реплицируемых по последнему
     снимку.
   - ИИ врагов выбирает цели заново. `NetId` новой эпохи не пересекаются со старыми.
   - Остальные шлют новому хосту `Rejoin { last_event_id }`. Если у клиента событий больше, чем у
     нового хоста, он досылает их хвост: все игроки получали один упорядоченный поток, отличаться может
     только хвост в полёте.
4. **Пока идёт смена,** у всех мир стоит, сверху надпись «Смена хоста…». Свой луноход стоит,
   враги замирают.

Пакеты с эпохой меньше текущей отбрасываются: прежний хост, вернувшийся из фона, не перебьёт нового и
переподключается клиентом. Если остался один игрок, он становится хостом и играет один. Если недоступна сама служба комнат, забег идёт по уже открытым соединениям, а при уходе хоста
кончается, как при прямом подключении.

*Альтернатива:* выбор нового хоста самими клиентами (наименьший номер). Отклонено: при разрыве сети
двое могли бы стать хостами сразу.

### Переподключение через службу
- Игрок, потерявший сеть, заново соединяется со службой с `{ code, player, session_token }` и
  получает адрес текущего хоста: он мог смениться за время обрыва. Дальше — `Rejoin` из `net-coop`.
- Место держится 30 секунд.
- Телефон, сменивший Wi-Fi на мобильную сеть, часто не обрывается вовсе: QUIC переносит соединение
  на новый адрес.

### Меню
- Подэкран «Вместе» в `menu.rs`: «Создать игру», «Войти по коду», «Быстрая игра».
- Для ввода кода переиспользуется экранная клавиатура имени рекорда, с ограничением на 4 символа
  алфавита.
- Ошибки службы — `RoomNotFound`, `RoomFull`, `RunInProgress`, `ServerBusy`, `WrongVersion` — один
  экран сообщения с возвратом.
- Соединение со службой открывается только по выбору пункта, в одиночной игре сеть не трогается.

### «Поделиться»
- Android: JNI (`jni` 0.22, `ndk-context` — уже приходят с `android-activity`) — `Intent.ACTION_SEND`
  и `Intent.createChooser`, вызов из `src/android.rs`.
- iOS: `UIActivityViewController` через `objc2-ui-kit` из `src/ios.rs`.
- Компьютер: `arboard` 3.x — буфер обмена.

### Пределы и приватность
- В памяти службы — комнаты и счётчики создания по адресу, сбрасываемые раз в минуту.
- Ретранслятор видит адреса только в памяти, пока соединение открыто.
- Ни адреса, ни ключи узлов, ни коды не пишутся в журнал: уровень `tracing` для `iroh` и `iroh_relay` —
  `warn`, и свои строки без адресов.
- Раз в минуту в журнал идёт одна строка: комнаты, игроки, смены хоста, байт ретранслятора за минуту.
- Keep-alive службы комнат — 10 с: NAT держит запись UDP 30–120 с. Таймаут простоя — 30 с.

### Выкладка
`scripts/deploy-server.sh <хост>`:
1. сборка `cargo build --release` для `x86_64-unknown-linux-gnu` из `server/`;
2. `scp` бинарника и юнита;
3. `systemctl restart`.

Юнит `server/space-guard-server.service` запускает службу под отдельным пользователем без
привилегий, порт 443 — через `AmbientCapabilities=CAP_NET_BIND_SERVICE`. Брандмауэр открывает
TCP 443, UDP 7447 и UDP 7842.

## Risks / Trade-offs

- [Через ретранслятор задержка больше, чем напрямую, на 10–40 мс по Европе] → Требования `net-play`
  к задержке проверяются и через ретранслятор (прямой путь закрыт брандмауэром). Сервер — в Германии.
- [Миграция теряет последние до 2 секунд нестабильного состояния] → Таймеры и здоровье — из
  контрольной точки, положения — из последнего снимка, постоянные изменения — из журнала. Враг может
  чуть сместиться и заново выбрать цель. Это заметно меньше, чем конец забега.
- [Новый хост — слабый телефон] → Выбор по классу устройства; на слабом хосте профиль уже снижает
  число обломков и огней.
- [Хост вернулся из фона и считает себя хостом] → Эпоха: его пакеты отбрасываются, служба шлёт ему
  `HostChanged`, и он переподключается клиентом.
- [Трафик VPS] → Через ретранслятор идут только пары без прямого пути. Счётчик в журнале. 20 ТБ
  тарифа — около 60 Мбит/с в среднем, это сотни комнат при 70 % прямых пар.
- [Сертификат на IP: смена IP VPS ломает старые версии] → Корень свой, сертификат перевыпускается
  на новый IP без смены корня. Адрес — константа с запасным DNS-именем на будущее.
- [Закрытые ключи службы и корня потеряны] → Резервная копия у владельца VPS вне сервера, в
  репозиторий не класть.
- [JNI «Поделиться» на `NativeActivity` без Gradle] → Только системные классы Android. Если не выйдет,
  копировать в буфер через `ClipboardManager` по тому же JNI.
- [Сервер упал — новые комнаты недоступны] → `systemd` перезапускает службу. Начатые забеги с прямым
  путём продолжаются, одиночная игра от сервера не зависит.

## Migration Plan

1. Сервер выкладывается до выпуска игры с пунктом «Вместе».
2. Ключ службы, адрес и корень вписываются в константы.
3. Новая версия игры выкладывается.

Откат — скрыть пункт «Вместе» (константа `ROOMS_ENABLED`), прямое подключение для разработки
остаётся.
